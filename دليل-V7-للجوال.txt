لوحة التحكم V7 — تحديث من الهاتف
=================================
هذا ملف تحديث جزئي؛ لا تحذف باقي ملفات الموقع أو الصور أو الصفحات القديمة.

1) احتفظ أولًا بنسخة احتياطية من site-data.json الحالي؛ يحتوي على التعديلات التي نشرتها سابقًا.
2) فك الضغط، وارفع الملفات المبينة هنا إلى جذر مستودع GitHub (استبدل الملفات المطابقة للأسماء):
   admin.js, store.js, data.js, content-hub.js, content-hub.css,
   events.html, careers.html, research.html, videos.html, awareness.html, firestore.rules.
3) إذا كان site-data.json في GitHub يحتوي على تعديلات مهمة سابقة: لا تستبدله بالنسخة المرفقة. سيقوم store.js الجديد بإضافة مجموعات الأقسام الجديدة تلقائيًا عند الاستيراد، ثم تصديرها في ملف البيانات القادم.
   إذا كنت تستعمل البيانات الافتراضية تمامًا: يمكن رفع site-data.json الجديد.
4) رابط لوحة التحكم بعد الرفع: https://azezalal65255-art.github.io/dr-munir-clinic./admin.html
5) الآن ستجد أقسام: المؤتمرات والفعاليات، الوظائف المعلنة، البحوث والدراسات، مكتبة الفيديو، المقالات التوعوية.
6) في «تحرير محلي» يمكنك إضافة المحتوى وتعديله، ثم: «نظرة عامة» -> «تنزيل بيانات الموقع» -> رفع site-data.json جديد إلى GitHub. هذا ليس نشرًا مباشرًا.
7) للنشر التلقائي: فعّل Firebase داخل لوحة الإعداد (firebase-setup.html) ثم أنشئ مستخدم الإدارة وامنحه صلاحية داخل مجموعة admins؛ راجع قواعد Firestore الجديدة وطبّقها في Firebase Console. عند تفعيل Firebase يصبح حفظ المحتوى نشرًا مباشرًا بدون رفع GitHub كل مرة.
8) الصور: أدخل اسم الملف الفعلي (مثال photo-ultrasound.jpg) أو رابط HTTPS. لا ترفع صورة طبيب أو طبيبة آخرين، فقط معدات وأجهزة وفحوصات موثوقة الحقوق.
9) الفيديو: الرابط يجب أن يكون من YouTube أو Facebook أو Vimeo، وليس فيديو مضمّنًا في GitHub.
10) لا توجد وظائف أو فعاليات أو بحوث مفترضة. لن تظهر في الموقع حتى تنشر محتوى معتمدًا.
11) الشكاوى والاستبيانات لا تخزن في GitHub أو قاعدة البيانات هنا؛ ما زالت تنتقل إلى واتساب بعد ضغط المستخدم «إرسال» في واتساب.

الحماية: GitHub Pages استضافة ثابتة. مجرد ظهور لوحة التحكم لا يحميها بكلمة مرور في الوضع المحلي. احفظ كلمات المرور داخل Firebase Authentication فقط، ولا تضع بيانات مرضى أو سير ذاتية أو معلومات خاصة في site-data.json.

خطوات التحقق من حساب Firebase (قبل التفعيل):
- افتح https://console.firebase.google.com/ في Chrome وسجل الدخول بحساب Google.
- راجع قائمة المشاريع. وجود المشروع في القائمة لا يعني بالضرورة أن موقعك متصل به.
- للتحقق من ربط الموقع: راجع ملف config.js في GitHub وابحث عن projectId غير فارغ.
- إذا لم تجد مشروعًا، أنشئ مشروعًا جديدًا؛ يمكنك اختيار خطة Spark المجانية وترك Analytics غير مفعل.
- Firebase Authentication: فعّل Email/Password ثم أنشئ مستخدمًا خاصًا بالإدارة.
- Firestore Database: اختر Production ثم الصق محتويات firestore.rules في تبويب Rules واضغط Publish.
- Firebase Web App: انسخ إعدادات المشروع إلى مساعد firebase-setup.html، واستخرج config.js وارفعه لمستودع GitHub.
- بعد تسجيل الدخول بلوحة admin.html انسخ UID، وأنشئ داخل Firestore > Data وثيقة admins/{UID} بالحقل active من النوع boolean بقيمة true.
- لا ترفع CV أو شكاوى تحتوي بيانات حساسة على GitHub؛ النصوص المنشورة للعامة فقط في أقسام المحتوى.
- خطأ شائع تم إصلاحه هنا: روابط Firebase SDK يجب أن تبدأ https://www.gstatic.com/firebasejs/12.19.0/.
