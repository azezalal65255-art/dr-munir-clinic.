عيادة د. منير الشكري — موقع GitHub Pages + Firebase

1 إنشاء مشروع Firebase

افتح Firebase بحساب Google الذي تملكه، واضغط Create a project. أضف تطبيق ويب Web (علامة </>) ثم اختر له اسمًا مثل Dr Munir Clinic.

فتح Firebase Console ↗

لا حاجة لنقل موقعك من GitHub Pages؛ Firebase ستستخدم لتسجيل الدخول وحفظ المحتوى.

2 تفعيل البريد وكلمة المرور

  1. من Firebase افتح Authentication → Sign-in method.
  2. فعّل Email/Password فقط واضغط Save.
  3. من تبويب Users اضغط Add user، وضع بريدك الشخصي وكلمة مرور قوية وخاصة.
  4. من Authentication → Settings → Authorized domains أضف azezalal65255-art.github.io عند الحاجة.
لا ترسل إليّ كلمة المرور، ولا تنسخها إلى GitHub أو إلى مربع الإعداد أدناه.

3 إنشاء قاعدة بيانات Firestore وتطبيق قواعد الحماية

  1. افتح Firestore Database → Create database، واختر قاعدة بيانات افتراضية (default) ووضع الإنتاج Production.
  2. بعد إنشائها افتح Rules، ثم اضغط «نسخ قواعد Firestore» هنا.
  3. استبدل القواعد في محرر Firebase بالنص المنسوخ، ثم اضغط Publish. رفع ملف القواعد إلى GitHub وحده لا يفعّل الحماية.
تنزيل القواعد

4 استخراج بيانات التطبيق وتحميل config.js

في Firebase افتح Project settings → Your apps → Web app → SDK setup and configuration → Config، ثم انسخ الجزء الذي يحتوي على firebaseConfig وضعه هنا. هذه بيانات تعريف تطبيق الويب العامة وليست كلمة مرور.

سيُنشئ المتصفح ملف config.js على هاتفك؛ لا تُرسل الكود إلى أي موقع خارجي. ارفع هذا الملف فقط إلى جذر مستودع GitHub واستبدل config.js القديم، ثم اضغط Commit changes.

5 منح حسابك صلاحية المسؤول

بعد ظهور تسجيل الدخول في لوحة الإدارة:

  1. افتح admin.html وسجّل الدخول بالبريد وكلمة المرور اللذين أنشأتهما في Firebase.
  2. ستظهر رسالة بأن الحساب ليس مسؤولًا بعد، وأسفلها زر لنسخ معرّف UID الخاص بحسابك.
  3. افتح Firebase → Firestore Database → Data.
  4. أنشئ Collection بالاسم admins (حروف صغيرة).
  5. أنشئ Document واجعل Document ID = UID المنسوخ بالضبط.
  6. أضف Field باسم active من النوع boolean بقيمة true، ثم احفظ.
  7. ارجع إلى لوحة التحكم وسجّل الدخول مجددًا. لا تفتح صلاحية المسؤول لجميع الزوار.

6 تهيئة محتوى الموقع

أول مرة فقط، ستظهر داخل لوحة التحكم عبارة تهيئة المحتوى الافتراضي. اضغطها لإنشاء بيانات العيادة والخدمات والمقالات الحالية في Firestore. لا تضغطها إذا كانت قاعدة البيانات تحتوي بالفعل على بيانات منشورة تريد الاحتفاظ بها.

بعد ذلك يمكنك تعديل خدمات العيادة والمقالات والأسئلة والتواصل والدوام مباشرةً، دون إعادة رفع ملفات HTML.

7 الصور والحجوزات: اختياري

الصور: يمكنك دائمًا رفع الصور إلى GitHub ثم وضع اسمها في لوحة التحكم، مثل doctor.jpg؛ هذا لا يتطلب خدمة تخزين مدفوعة. أما زر رفع الصورة المباشر داخل لوحة الإدارة فيستخدم Firebase Storage ويتطلب خطة Blaze وتفعيل الفوترة.

الحجوزات: تكون مغلقة افتراضيًا. إذا رغبت بفتح طلبات المواعيد لاحقًا فانتقل إلى إعدادات الموقع وفعّل استقبال طلبات المواعيد بعد التأكد من قواعد الحماية وأن هناك من يتابع الطلبات. النموذج لا يؤكد الحجز تلقائيًا.

للصور المباشرة فقط: فعّل Storage من Firebase، ثم انسخ قواعد التخزين المناسبة واضغط Publish.

تنبيه: قد يترتب على استخدام Blaze رسوم فعلية. حافظ على إعداد حدود الميزانية والتنبيهات في Google Cloud. لا تستخدم صور المرضى أو بيانات طبية حساسة دون الموافقات اللازمة.
